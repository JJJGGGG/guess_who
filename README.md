# Guess Who

Two-player online Guess Who. A single Node app: Express serves the JSON API (`/api/*`), socket.io (`/socket.io`) and the React client, all from one origin.

```
server/   Express API, socket.io, client serving (entry: server/index.js)
client/   React + Vite + Tailwind app
prisma/   SQLite schema and migrations
dist/     built client (generated by `npm run build`)
```

## Setup

Requires Node 22+ (developed on Node 24).

```sh
npm install
cp .env.example .env      # then set SESSION_SECRET (e.g. `openssl rand -hex 32`)
npx prisma migrate deploy # creates prisma/dev.db
```

## Development

```sh
npm run dev
```

Open http://localhost:3000. Vite runs inside Express, so client changes hot-reload and changes under `server/` restart the process.

### Testing from other devices on your LAN

Phones need HTTPS. Create a cert with [mkcert](https://github.com/FiloSottile/mkcert) and keep it outside the repo (never commit it).

1. Install mkcert and create the cert (once per computer). `mkcert -install` makes your own computer's browsers trust it for `localhost`:

   ```sh
   sudo apt install mkcert libnss3-tools   # Debian/Ubuntu; macOS: brew install mkcert nss
   mkcert -install
   mkdir -p ~/.config/guess_who
   mkcert -key-file ~/.config/guess_who/key.pem -cert-file ~/.config/guess_who/cert.pem localhost 127.0.0.1 ::1
   ```

2. Add to `.env` (absolute paths; `~` is not expanded there):

   ```sh
   HOST=0.0.0.0
   TLS_KEY=/home/<you>/.config/guess_who/key.pem
   TLS_CERT=/home/<you>/.config/guess_who/cert.pem
   ```

3. Run `npm run dev` and open `https://<your LAN IP>:3000` on the phone (`hostname -I` shows the IP). The phone doesn't trust the cert, so accept the warning once per session: Chrome **Advanced → Proceed**, Safari **Show Details → visit this website**. The page, API and websocket share one origin, so that one exception covers everything. It works for any LAN IP, so nothing needs regenerating when your IP changes.

   Traffic is still encrypted, but the phone doesn't verify the server's identity. That's fine for testing on a network you trust.

## Production

```sh
npm run build   # prisma generate + type-check + build client into dist/
npm start       # apply migrations, then serve on $PORT with NODE_ENV=production
```

TLS is expected to be terminated by the hosting platform (Render, AWS load balancer), which forwards plain HTTP to Node. In production the server binds to `0.0.0.0` and trusts one proxy hop.

On Render: one Web Service, build command `npm ci --include=dev && npm run build`, start command `npm start`, env `SESSION_SECRET` (and optionally `GRACE_SECONDS`). Don't set `NODE_ENV` in the dashboard, since the build needs dev dependencies.

## Environment variables

| Variable | Required | Description |
|---|---|---|
| `SESSION_SECRET` | yes | At least 32 bytes, signs player tokens |
| `GRACE_SECONDS` | no | Seconds a disconnected player keeps their seat (default 30) |
| `PORT` | no | Port to listen on (default 3000) |
| `HOST` | no | Interface to bind (default `127.0.0.1` in dev, `0.0.0.0` in production) |
| `TLS_KEY`, `TLS_CERT` | no | Paths to a key and cert; when both are set, Node serves HTTPS (for LAN testing) |
